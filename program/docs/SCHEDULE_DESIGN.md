# 設計: スケジュール（ScheduleView を移した。版 3.57.0）

利用者の依頼（2026-10-26）: 「別リポジトリの ScheduleView の機能を、スケジュールというタブを新設して移植実装してください」。

この文書は「何を移し、何を LotScope の仕組みに置き換えたか・なぜか・何で確かめたか」を残す。

## 1. ScheduleView の機能と、LotScope での受け持ち

ScheduleView（`satoshi-hello-vlioilv/schedule-view`。版 12.0.0 で Python＋Flask から Rust の exe へ移した独立アプリ）は、
CM3 スケジューリングシステムの設備ごとの作業予定（L-1・L-2・L-3）を一覧で見て、仕掛台帳（`LOTNOW.sqlite3`）の項目を突き合わせて並べる。
LotScope にはすでに、同じ `LOTNOW.sqlite3` を手元へ写して読むデータ元「仕掛」と、どのデータ元にも使える一覧・結合・表示列・Excel がある。
同じ物を 2 つ持たないよう、**ScheduleView にしか無い物だけを移し、ほかは LotScope の仕組みに乗せた**。

| ScheduleView の物 | LotScope での受け持ち | 理由 |
|---|---|---|
| CM3 の取得と整形（`cm3_client.py`: 行の区分・停止の文・点検・文字化けの直し・日付の補い・開始予定・パス） | **移した**: `app/services/cm3_schedule.py`（旧版の Python をそのまま、LotScope の書き方で） | LotScope に無い物 |
| 設備のタブ・HOT コイル作業順（`app.py` の `hot_list`） | **移した**: `app/services/schedule.py`（`Schedules.build_hot`）・`app/routes/schedule.py` | LotScope に無い物 |
| 台帳の写し（共有から手元へ・`-journal`／`-wal` のときは写さない・`quick_check`） | データ元「仕掛」の写し（`db_mirror.py`。DataRelay の作法に合わせた、より確かな写し） | 同じファイルを 2 回写さない |
| 突合せのキー（台帳設定: スケジュールの項目＝台帳の列。複数の組・NFKC・数は数） | データ元の結合（`data_join.py`。スケジュールの既定の結合: ロットNo＝仕掛のロット番号の列。鍵の比べ方は同じ考え） | 結合の画面（マスタ管理の「データ元」）をそのまま使える |
| ロット番号の列の自動判定 | 仕掛の写しの実際の列から決める（`routes/schedule.py` の `_resolved`。ﾛｯﾄ番号／ロット番号 の違いを吸収） | 結合を保存した後も効く |
| 列の設定（並び・表示・表示名・計算列・読み替え・色分け）・設定ファイルの書き出し | 表示列の設定・式・色付け・表示の設定の書き出し（今までの一覧の部品） | 品質異常・作業実績・仕掛と同じ操作で使える |
| 既定の列（前工程＝実績_設備ｺｰｽ の最後・釜番＝設計_PIT炉番炉順・次の設備〈隠す〉・設備と開始予定は隠す） | 表示列の既定（`lotlist-columns.js` の `setDefault`。保存した設定があればそちらが勝つ） | 開いてすぐ ScheduleView と同じ列 |
| 検索・並べ替え・次工程の札 | 一覧を検索・見出しで並べ替え・スライサー／値で絞る | 同上 |
| 配色（停止・点検・自分の設備が次工程・日付の境・縞） | 行の区分の色（`lotlist-schedule.css`。色の意味は ScheduleView と同じ） | |
| 点検の行の言葉 | 参照先「スケジュールの点検の行の言葉」 | 全員で同じ判定 |
| CSV／Excel 出力（見えている形のまま） | Excel に出力（今までの一覧の部品。出力の条件に設備・表） | |
| 自動更新（60 秒ごと）・更新 | 画面が 20 秒ごとに鮮度を尋ね、サーバーは古くなった設備を裏で取り直す（参照先「スケジュールを取り直す間隔」既定 60 秒）。新しい予定が来たら押さなくても出し直す。「元データ」の札を押すと今すぐ取り直す | |
| CM3 の画面を開く・ロット番号のリンク | 設備のタブの行の「CM3 の画面を開く ↗」（いつものブラウザ）・ロット番号の虫眼鏡（LotDsp）とロット番号を押すと計算へ取り込み | |
| 配布・更新・ショートカット（exe） | LotScope の配布・更新のまま | 1 つのアプリになる |

## 2. つなぎ方

```
 CM3 ──(cm3_schedule.py: 取得・整形。同じ設備は同時に 1 本・HOT の設備は同時に)──▶ 設備ごとの表「予定」
        （この PC の作業場所 db_cache/schedule/<設備>.g<世代>.sqlite3。中身が変わったときだけ新しい世代）
                     │ データ元「スケジュール」（sch）の結合（data_join.py。既定: 仕掛を左外部結合）
                     ▼
        一覧・スライサー・集計表・ダッシュボード・Excel（/api/src/sch?equip=<設備>。仕掛と同じ口・同じ問い合わせ）
 HOT コイル作業順 … HOT の設備の結合した答えから、前工程（実績_設備ｺｰｽ の最後）が HOT・次の設備（残仕掛設備ｺｰｽ の最初）が
                    その設備・1 パス目の行を、完了予定の順に並べた表「HOT」（/api/src/sch?equip=__HOT__）
```

- データ元「スケジュール」は組み込みの元（`data_sources.py` の BUILTINS。kind `cm3`）。見出しのタブは「スケジュール」（暦の絵）。
  タブの並びは、ほかの元の後ろ（今のタブの並びを崩さない）。
- CM3 に届かなくなったときは、前に取れた予定を出し続け、「元データ」の札に理由を出す（一度も取れていない設備は理由つきの 502）。
- 設定: 配った設定 `config/appsettings.json` の `schedule`。CM3 の URL・端末の IP・設備・点検の言葉・取り直す間隔は参照先マスタで直せる（全員に効く）。

## 3. 評価関数（何で確かめたか）

`tests/test_schedule.py`（13 件）:

| 物差し | 中身 |
|---|---|
| 旧版の答えの記録 | ScheduleView の `desktop/tests/golden/python.json`（旧版の Python を動かした答え）のうち入力と答えが対の物を `tests/fixtures/schedule_golden.json` に写し、字の直し 26 通り・値のそろえ方 25 通り・列名 9 通り・整形の誤り 4 通りが同じ |
| 整形 | 作り物の CM3（`tests/schedule_fixture.py`: 日付の繰り上がり・2 パス・停止の切れ端・点検板・文字化け・HTML の文字参照・仕掛に無いロット・前工程が HOT）で、区分・停止の文・開始予定・パスが正しい |
| 一覧と突合せ | 本物と同じ HTTP で作り物の CM3 に問い合わせ、一覧の口の行が整えた行と同じ・仕掛の列が仕掛のファイルを素直に引いた答え（oracle）と同じ・数が合う・保存した結合でも当たる |
| HOT | ScheduleView の決まりを素直に当てた答え（oracle）と、並び・前工程・釜番・除いた数が同じ |
| 覚え | 同じ中身なら置き直さない・変われば新しい世代で前の世代を消す・届かなくなっても前の予定と理由・同じ設備は 1 本・HOT の設備は同時に |
| 評価関数が甘くないか（わざと壊す） | HOT のパスの決まり・日付の繰り上がり・停止の文のつなぎ方・ロット番号の列の吸収・飾りの項目を停止の文から除く、の 5 か所をそれぞれ壊すと、どれも試験が落ちた |

## 4. 分からないこと・使う前に確かめること

- 本物の CM3（`http://nlmfangyweb1a:9085`）には、この開発の環境からは届かない。答えの形は ScheduleView の仕様書（`CM3_API_spec.md`）と旧版の記録に合わせた。
- 本物の仕掛台帳の HOT の列（実績_設備ｺｰｽ・残仕掛設備ｺｰｽ・設計_PIT炉番炉順）の名前は ScheduleView の既定のまま。違えば設定 `schedule.hot` で直す。
- ScheduleView の「列の設定」で作った設定ファイル（`view_settings.json`）は、LotScope の表示列の形と違うため読み込めない（列は表示列で作り直す）。
