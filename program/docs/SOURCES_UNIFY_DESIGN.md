# データ元を 1 つの仕組みに（版 3.58.0）

利用者の要望（2026-10-28）:

- 「データ元」の汎用の仕組みの中に、品質データ・作業実績も載せる（同じ形で登録・設定・処理する）
- 「つなぎ先」に散っていた設定（参照先・作業実績）を、データ元の接続の設定項目として載せる
- タブの名前: 品質データ → **品質**、作業実績 → **実績**
- データ元のグループを消せる・組み込みの元の名前を変えられる
- 見出しに出すタブを権限で決められる（タブが多くても扱いやすい形で）
- 「ロット」という名前の、ロット番号ではない列がロット番号扱いされるのを、元ごとに解除できる

## 1. 接続の設定（services/data_sources.py の CONN_SPECS・CONN_BIND・CONN_FILE）

どの元も、同じ形の「接続の設定」の欄を持つ。欄の種類は 10 個（場所・表・フォルダ・ファイル名の決まり・CM3 の URL・端末の IP・設備・
点検の行の言葉・確かめる間隔・古さの警告）と、ロット番号の列。元ごとに、どの欄を持ち、値をどこに置くかを決める（`conn_bind`）:

| 元 | 欄 | 値の置き場 |
|---|---|---|
| 品質（lot） | 場所・表・確かめる間隔・古さの警告 | 参照先の `lot_list.*`（配った設定を既定に） |
| 実績（work） | フォルダ・ファイル名の決まり・確かめる間隔・古さの警告 | 参照先の `work_log.*` |
| スケジュール（sch） | CM3 の URL・端末の IP・設備・点検の行の言葉・確かめる間隔 | 参照先の `schedule.*` |
| 仕掛・足した元（file） | 場所・表・確かめる間隔・古さの警告 | このマスタ（data_sources）の行の列 |
| 結合した表（view） | （場所・間隔は元の物） | — |
| どれも | ロット番号の列 | このマスタの行の「ロット番号の列」 |

- 画面は置き場の違いを見せない（同じ欄・同じ「保存」）。API は `GET /api/sources`（`conn`: 欄の並び・値・既定・いま効いている値・版）と
  `PUT /api/sources/<キー>/conn`（1 項目を置く。空なら既定へ）・`POST /api/sources/<キー>/conn/check`（保存の前に確かめる）
- 参照先の項目のうちデータ元に載せた物は `page: "sources"`。データ元ではない接続（ロット問い合わせの URL・更新の置き場・ブラウザ）は
  `GET /api/sources` の `others` で返し、データ元の頁の「そのほかの接続」で直す
- 足した元の「確かめる間隔」「古さの警告」は、写し（work_log.Mirrors）の読み方 `read_params` に効く（空なら設定 `sources.defaults`）
- `PUT /api/sources/<キー>` は、送らなかった列をいまの行のまま残す（欄の一部だけを直す元でも、ほかの列を消さない）

## 2. 名前とグループ

- 組み込みの元の名前は 品質・実績・仕掛・スケジュール。どれも `POST /api/sources/<キー>/quick`（表示名）で変えられ、空にすると元の名前に戻る
- 見出しのタブ「品質」「実績」はその元の名前を使う（名前を変えればタブの名前も変わる。見出しのタブの名前を右クリックで変えた物はそちらが勝つ）
- グループの名前を変える・消す: `POST /api/sources/groups {from, to}`（to が空なら消す＝元はグループなしへ。元そのものは消さない）。
  役割「マスタ」の元は、消すと自動の「マスタ」へ戻らないよう印 `-`（NO_GROUP）を置く

## 3. ロット番号の列（lot_list.lot_column の override）

- 元ごとに「自動（名前で探す: ロット番号・ﾛｯﾄ番号・ロット№・LTNO → 名前に「ロット」を含む最初の列）」「なし（`-`）」「この列」
- 一覧・まとめ・集計（pivot.Part）・稼働（operation）の全部が同じ決め方を使う。決めてある元は、デスクトップ版でも Python が答える（Rust は自動の決め方しか知らない）

## 4. 見出しのタブの権限（services/access.py）

- マスタ `tab_access`（管理のマスタ・共有）: タブごとに「出さない区分」（メンテナンス者・一般ユーザー・設備作業者）。
  人ごとの例外は access_permissions の行の「タブの例外」（{タブ: 出す|出さない}）。区分の決まりより人の例外が勝つ
- 開発者はいつも全部。ダッシュボードと計算は止めない（いつも出す）
- 画面は `/api/access/me` の `hiddenTabs` で、そのタブとデータ元を出さない。サーバーも、出さないタブの元の一覧・集計の問い合わせを断る（`common.tab_denied`）
- `GET/PUT /api/masters/tabaccess`（決まり・タブの一覧・区分・例外の数・版）
