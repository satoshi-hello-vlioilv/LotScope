# 異常ロット一覧（品質データ）の設計

## 目的

WaveLog の品質データ（`SIKADEF.sqlite3`）を一覧で開き、WaveLog と同じ絞り込みで対象を絞って、ロット番号を押すだけで転写計算の「検索」と同じ取込をする。

## 元データの読み方（WaveLog `backend/db_mirror.py` と同じ方式）

| 項目 | 内容 |
|---|---|
| 元 | 設定 `lot_list.source`（既定 `\\Nlmsrvngy03\Read\【New】仕掛\台帳\SIKADEF.sqlite3`） |
| 写しの置き場 | `%LOCALAPPDATA%\LotScope\db_cache\lot_list.g<世代>.sqlite3`、台帳 `_mirror.json` |
| 写し方 | 書き手（DataRelay）と干渉しない作法: 同じフォルダに書き手の作業中の印（DataRelay の `.<名前>.<番号>.incoming`・SQLite の `-journal`・`-wal`）があれば写さない → SQLite として開かず、置き換えを許す開き方（Windows の `FILE_SHARE_DELETE`。`fsio.open_shared_read`）でファイルを丸ごと一気に写す → 写す前後の (サイズ, 更新時刻) が同じか → `PRAGMA quick_check(1)` とテーブルの有無で検査 → 世代名へ `os.replace` → 台帳を一時ファイル経由で置き換え。見送ったら 5 秒空けて写し直す |
| 書き手（DataRelay）の公開 | 公開先の横へ隠しファイル `.<名前>.<番号>.incoming` を書き切り、`os.replace` で丸ごと入れ替える（中を書き換えない）。ほかが公開先を開いていると Windows では入れ替えが「使用中」で拒まれ、20 秒粘ってだめなら `<名前>.pending_<日時>` に保留して次の実行で入れ替える。だから写しの係は、公開の最中に開かない・開いている時間を最短にする・共有を直接読まない。試験は `tests/test_mirror_writer.py`・`desktop/tests/mirror_writer.rs`（Windows の本物の規則は CI） |
| 変わったかの判断 | 元の (パス, サイズ, 更新時刻 ns)。パスも印に含めるので、元を差し替えたら前の写しは使わない |
| いつ | 背景スレッド: 起動直後に1回（済むまで一覧は待つ・最大 30 秒）→ `refresh_seconds`（既定 60・最小 10）ごと。届かなくなった最初の1回だけ 10 秒後に取り直す。stat は前に届いていた元なら 0.3/0.7/1.5 秒待って取り直す |
| 共有に触る場所 | 背景スレッドと「再読込」（`POST /api/lotlist/refresh`）だけ。一覧の要求と鮮度の問い合わせ（`GET /api/lotlist/source`）は共有を stat しない（台帳の印から言う） |
| 壊れた・届かない | 前の写しを使い続ける。写しがまだ無いときも元を直接は読まない（開くと書き手の入れ替えを止めるため）。一覧は「まだ手元へ写せていません（理由）」と答え（`kind: copying`・503）、画面は 4 秒ごとに引き直す |
| 古い世代 | 消せたときに消す（Windows で読んでいる間は消えないので、次の周回でまた試す） |
| 開き方 | `file:…?mode=ro`（UNC は `file:////server/share/…`）。開く前に stat しない。`CStr`・`Val`・`Nz` を登録 |

実装: `app/services/db_mirror.py`（`DbMirror`）、`app/services/sqlite_ro.py`。

## 一覧の問い合わせ（WaveLog `/api/table` と同じ）

`GET /api/lotlist?table=&page=&page_size=&search=&filters=&sorts=`

- `search`: 全列を `CStr(列) LIKE %q%` の OR
- `filters`: `[{column, op, value}]` を AND（最大 20）。op と SQL は WaveLog と同じ（`contains` `not_contains` `eq` `neq` `starts` `starts_any` `ends` `gt` `gte` `lt` `lte` `empty` `not_empty`）。`gt〜lte` は `Val(CStr(列))` と数にしたパラメータで比べる
- スライサー: `in`（選んだ値のどれか。`key` があれば見えている値で比べる）と、計算列の `tuple_in`（版 3.20.0〜）:
  `{op:"tuple_in", columns:[式が使う元の列（1〜4）], value:"[[値, …], …]"}`。組ごとに `列 IS ?` の AND を OR でつなぐ（NULL の組も当たる・型のまま比べる）。
  計算列の式は画面（`list-formula.js`）にしか無いので、`/slicer?columns=[…]` で元の列の値の組と件数（`slicer_combos`。件数の多い順・同じ件数は値の順）を返し、
  画面が組ごとに見えている値を計算して足す。選んだ値になる組を `tuple_in` で返す。デスクトップ版の Rust（`lotlist.rs`）も同じ（`lotlist_parity.rs` が突き合わせる）
- `sorts`: `[{column, dir}]`（最大 4）
- 列名は実在するものだけを SQL に入れ（`[ ]` で括る）、値はすべてパラメータ
- 表: 指定 → 設定 `lot_list.table` → `仕掛`・`品質情報`・`品質`・`保留` → 最初の表。ロット番号の列: `ロット番号`・`ﾛｯﾄ番号`・`ロット№`・`LTNO`
- 応答: `{table, tables, columns, lotColumn, rows, count, page, page_size, filters_applied, sorts, source:{at, mirrored, copiedAt, checkedAt, unreachable, reason}}`

実装: `app/services/lot_list.py`、`app/routes.py`。

## 件数の行を 1 段に（版 3.25.0〜。`lotlist-active.js`）

利用者の指示「フィルタの段が 1 段、機能のボタン類の段が通常は 1 段ですが、表示が増えたりすると 2 段になったり増えていきますが、1 段のままスッキリ使いたい」。
以前は、まとめ 3 段＋並べ替え＋スライサーで選んだ値＋色付け＋書式で件数の行が 3 段になり（2 段目が段と並べ替えの札、3 段目は拡大と頁送りだけ）、一覧が約 90px 下がった。
性質の違う物（効いている物の要約・見方の切り替え・行き来）が 1 本に平たく並び、選んだ値・色付け・書式は上の段のボタンにもあって 2 か所に出ていた。

| 部品 | 動き |
|---|---|
| 効いている物のタブ | まとめ・並べ替え・選んだ値（スライサー）・色付けを、種類ごとに 1 つのタブ（数・種類・中身の名前）。効いている種類だけ出す。狭いときは名前から省略し（種類と数は残す）、全部はタブの説明（title）に |

## WaveLog との違い（意図して持ち込まなかったもの）

- 登録した条件・プリセットは **この PC に** 覚える（WaveLog はマスタ DB に置いて PC 間・利用者ごとに共有）。このアプリには利用者の区別と条件のマスタが無いため。
- 「よく使う条件」の利用回数、変数（`{使用設備}`）、列の表示名・列レイアウト・並べ替えの読み替えルール、品質データの結合、全件の背景読み込みは持ち込んでいない（1ページ最大 2,000 件）。
  ページの中の行は、見える分と上下に 1 ページずつだけ描く（版 3.24.0〜。下の「行を描く範囲」）。

## 画面の位置づけ

- 起動したときの画面（ヘッダーのタブ「異常ロット一覧」）。もう1つのタブ「転写・ピッチ計算」は、検索欄から LotDsp へ直接問い合わせる従来の導線。
- タブは WAI-ARIA のタブ（`role=tablist/tab/tabpanel`）。← → でタブを移り、Alt+1 / Alt+2 でどこからでも切り替える。
- 一覧と計算を行き来しても、一覧の条件・検索・ページ・並べ替えはそのまま（戻ったときは今の写しで引き直すだけ）。計算のタブには、いま取り込んでいるロット番号を添える。

## ロット番号を押したとき

計算画面へ切り替え、検索欄へロット番号を入れて `runSearch()`（検索ボタンと同じ関数）を呼ぶ。取込中なら押し直しを促す。一覧へ戻ると、取り込んだロットの行に印が付く。

ロット番号の横の虫眼鏡（版 3.21.0〜。「表の見せ方」の「機能」で出す／しまう）は、LotDsp でそのロットを開くだけ（取り込まない・画面も移らない）。
WaveLog と同じく、ロット番号と鋳造番号の linkkey の URL で開く（LOTDSP_IMPORT_DESIGN.md §1.6）。虫眼鏡はロット番号の字のすぐ横に、字の並びに揃えて置き
（利用者の指示）、そのぶんロット番号の列を広げる（幅を決めた列で入り切らないときは、番号の方を「…」で縮めて虫眼鏡は残す）。

## 日付の「今日から N 以内」

- 比べ方 `within_days`・`within_weeks`・`within_months`・`within_years`（値は 0 以上の整数）。サーバーは `ToDate(列) >= 今日−N`（`ToDate` は `sqlite_ro.to_date`。読めない値は NULL＝当たらない）。月・年は月末を丸める（3/31 の1か月前＝2/28）。
- 応答の `dateColumns`（値の8割以上が日付と読める列。写しの世代ごとに覚える）の列だけ、画面は「以内」を選べる。

## 並び・まとめ（版 3.7.0〜。以前の「ロット番号でまとめる」を広げた）

- 表ごとに覚える（`tpa.lotlist.arrange.v1` = `{表: {levels:[{column, dir, lot}], heads, suppress}}`）。「表の見せ方」の「並び・まとめ」と、見出しの右クリック「この列でまとめる」で決める。
- **段（levels）**: まとめる列を上から順に（最大4つ）。各段は ▲ asc／▼ desc。サーバーへ渡す並べ替えは「段の列（上から）→ 見出しで決めた並べ替え（段の列は除く）」で、合わせて最大4つ（`MAX_SORTS`）。
  見出しを押すと、まとめた列は段の ▲▼ を入れ替え、ほかの列は今までどおり「その中の並び」を決める。
- **ロット番号の段**: いちばん上の段がロット番号のときだけ `group=1` を渡し、サーバー（`lot_list.grouped_rows`）がロットを1か所に集め、ページの境目で切らない。
  このときだけ dir に `first`（並べ替えの順＝そのロットでいちばん上に来る行の順。並べ替えのキーには入れない）を選べる。
  深い段のロット番号には `group=1` を渡さない（サーバーはロットを表全体で集めるので、上の段の並びを崩す。上の段のあとにロット番号で並べ替えるだけで、同じ上の段の中で続く）。
- **並べ替えの鍵 = まとめの見分け**（版 3.12.0〜）: サーバーは並べ替えを生の値ではなく `SortKey(列)`（`sqlite_ro.sort_key`・Rust の `lotlist::sort_key`）で行う。
  空欄（NULL・空白だけ）は NULL、数と数に読める字（`' 54'`・`'1e-05'`）は数、ほかは前後の空白を除いた字。ロット番号の列は `SortKey(UPPER(CStr(列)))`（大小を同じに）。
  画面の見分け（`lotlist.js` の `sortKey`）も同じ決まりなので、同じ値と見た行は必ず隣り合う。
  （3.11.0 までは生の値で並べていたため、`' 100%'` と `'100%'`・NULL と `''`・字の `'54'` と数の 54 が離れ、画面では同じ値なのに
  まとまりが2つに割れ、2段目からの並びがそこで振り出しに戻った。字で入った数は 1, 10, 100, 11… の字の順になった）
- **見えている値でまとめる**（版 3.13.0〜。Excel のピボットと同じ）: 段の値の見分けは、列の書式・読み替えの後の「見えている字」（`levelKey`）。
  書式が値を丸めて見せる列は、サーバーにも同じ丸め方で並べさせる（並べ替えの `key`。`levelKeyKind` が列の書式から決める）:
  日付・時刻の書式で時刻を見せない形 → `date`（日）・`month`（年月）・`year`（年）＝ `ToDate(列)` の頭（日付と読めない値はその後ろで `SortKey`。読めた値には効かない）、
  数値の書式で小数の桁を決めた形 → `round:N`（数は `ROUND(SortKey, N)`、数でない値は `SortKey`）。時刻を見せる書式・書式なしは `SortKey`。
  サーバーが同じ鍵で並べられない列（読み替えで字を変えた列など）も、受け取ったページの中で段の見える値ごとに寄せる（`clusterRows`。最初に出た順・中の順は保つ）。
  （3.12.0 までは元の値でまとめていたので、日付だけを見せる「登録日時」のように時刻が違う行が別のまとまりになり、同じ日付が繰り返し出て、2段目もそこで振り出しに戻った）
- **画面で作るまとまり**（`lotlist.js` の `arrangedBody`）: 値が同じ行は続いている。段 d のまとまり＝段 0〜d の見える値がすべて同じ、続いた行
  （ロット番号は大小も無視。ロット番号が空の行はまとめない）。まとまりはそのページの中で数える。
  - 見せ方は `heads`×`suppress` の4つ（並べるだけ／見出し行／繰り返しを省く／見出し＋省く）を、小さな表の絵の札で選ぶ（`LOOKS`・`lookPicture`）。
    まとめているあいだは件数の横（`#llGroupBar`）に段の札（▲▼ で入れ替え・× で外す・＋ で表の見せ方）。
  - 見出し行（`heads`。既定は使う）: 2行以上のまとまりに付ける。先頭の列に ▾・段の名前の札（段が浅いほど濃い `ll-gk0〜2`）・段の値・件数（段の深さで字下げ `--ind`）、
    ほかの列はまとまりの中で同じ値ならその値、違えば「n通り」を淡く。列の数は同じ（色づけ `tintCss`・左に固定 `freezeCss` の nth-child・幅がずれない）。
    畳むと、その下の行と深い段の見出しを隠す（行は包む見出しを `data-anc` に持つ。畳んだまとまりは表ごとに開いているあいだ `tpa.lotlist.collapsed.v1`）。
  - 繰り返しを省く（`suppress`。既定は使わない）: 段の列で、上の行と同じ値・包む見出しにある値は、縦につながった面にする（`ll-blk0〜2`。段が浅いほど濃い。
    字は透明 `ll-rep`、行にマウスを乗せると薄く出る）。見出し行が無いときは、面の始まり（`ll-btop`）に値を太字で1回と件数（`ll-bn`。空欄は「（空欄）」）。
  - 見出しを付けないときは、まとまりの切れ目に線（`gb-0` 濃い〜`gb-2` 点線）。帯はいちばん上の段のまとまりごとに交互。
- 以前の `tpa.lotlist.features.v1` の `group: true` は、並び・まとめを一度も決めていない表で「ロット番号の段1つ（first）・見出し行」として引き継ぐ。
- **書き出し・読み込み**（版 3.12.0〜。「表の見せ方」→「並び・まとめ」→「ファイル」）: 表示列と同じ形のファイル
  `{kind: "tpa-lotlist-arrange", version: 1, savedAt, items: [{target: 表, body: {levels, heads, suppress, sorts}}]}`（`sorts` は「その中の並び」）。
  書き出しはこの表だけか、すべての表か（ほかの表に並び・まとめがあるときだけ尋ねる）。読み込みは、この表の分（1件だけのファイルはこの表へ）を当て、
  この表に無い列の段・並べ替えは飛ばして数を知らせる。ほかの表の分は、その表を開いたときに効くよう覚えるだけ。種類の違うファイルは理由を言って断り、何も変えない。
  保存・読み込みの部品は `TPA.saveJson`・`TPA.pickJson`（shared.js。表示列の書き出し・読み込みも同じ部品）。

## 一覧の拡大（版 3.12.0〜）

- 「表の見せ方」の窓（と、ボタンの下に開く窓）は、置いた位置から画面の下端までに収め、中でスクロールする（`TPA.placeBelow`。窓の大きさを変えたら収め直す）。
  3.12.0 までは高さを「画面 − 110px」で決めていたので、段を足すと下が画面の外へ出て、届かない所ができた。
- 件数の行の右（ページ送りの左）に 🔍 のつまみ（60〜200%・10% 刻み）。版 3.25.0 から、件数の行は「🔍 100% ▾」のボタンだけで、つまみ・刻み・戻すは押して開く面に（件数の行を 1 段に）。表（`#llGrid`）に CSS の `zoom` を掛けるので、列の幅・左に固定・見出しの貼り付きごと大きくなる。
- 一時的: この窓のあいだだけ覚え（`TPA.session` の `tpa.lotlist.zoom.v1`）、閉じると 100%。100% でないあいだは数字をアンバーの札にし、「100%に戻す」を出す。
- 列の幅の覚えは拡大前の px のまま。取っ手で幅を変えるときはマウスの動きを倍率で割り、幅を測るのは `offsetWidth`（拡大前）にする（`getBoundingClientRect` は拡大後）。
- 案は 5 つ（件数の行に置く／表の見せ方の中／一覧の右下に浮かべる／上の段のボタンと小窓／A−・A＋）を画像で比べ、件数の行に置く案に、拡大中だけ札と「戻す」を出す形を足した。

## 行を描く範囲（版 3.24.0〜。`virtual-rows.js`）

- 1 ページ（200〜2,000 行）の行は、見えている分と、その上と下に 1 ページずつ（合わせて約 3 ページ）だけ DOM に描く。描かない行の高さは
  上と下の空きの行（`tr.vr-pad`）で埋めるので、表の高さ・スクロールの長さ・つまみの位置は全部描いたときと同じ。
  送って、描いてある所の端まで半ページを切ったら、見えている所を真ん中に描き直す（残る行はそのまま。足りない端だけ足し、離れた端を外す）。
- 以前は 500 行×40 列＝セル 2 万個（DOM の部品 約 8.6 万個）を全部描いていたので、並べ替え・まとめ・拡大・式の窓の打鍵のたびに
  全部の配置を計算し直していた（4 倍遅い CPU で並べ替え 4.2 秒・並べ替えを外す 11.9 秒）。いまは描くのが約 100 行（部品 約 1.7 万個）。
- 一覧（`lotlist.js`）は行を文字列ではなく行の一覧（`model`: `{ key, html(), i, head, anc, wk }`）で持つ。HTML は描くときに作るので、
  カードの印（`is-carded`）・いまのロット（`is-current`）はその時の状態で付く。畳んだまとまり（`groupOpen`）・閉じた作業（`S.workOpen`）の行は
  描く一覧に入れない（以前は `hidden` で DOM に残していた）。カードで描いていない行を出すと、その行まで送る（`scrollTo`）。
- 行の高さは描いたときに測って覚え、まだ描いていない行は測った行の平均で見積もる。見積もりと違って行がずれたら、見ていた行が
  同じ所に残るようにスクロールを直す（ブラウザーの自動の合わせ `overflow-anchor` は切る）。いちばん下に居たら下に留める。
  数は見た目の px（表に CSS の `zoom` を掛けても、スクロールと同じ尺）で、空きの行の高さだけ zoom で割る。拡大を変えたら測り直す。
- 縞は行の番号で決める（`is-odd`。`:nth-child` だと描く範囲が動くたびにずれる）。CSS の行の `:nth-child` はやめた
  （先頭の行を外すたびに、残りの全部の行のスタイルを計算し直すため。まとめの地の色の強めは `:not(.vr-pad)` で）。
- 画面を隠している間（別のタブ・集計表）は描かない（高さを 0 と測らない）。出たときに大きさの見張り（`ResizeObserver`）が描く。
- 描いていない行はブラウザーのページ内検索（Ctrl+F）では見つからない（一覧の検索を使う）。
- 評価関数 `ui-eval-virtual.mjs`（描く行の数・隙間なく順に出る・全部の行が見える・縞・左の固定・拡大・まとめの畳み・作業の＋n・カード・隠して戻る）。

  左に固定は一覧の先頭の列を並べた図（押した列まで）。

  `tpa.lotlist.overflow.v1`（`ellipsis`／`clip`／`wrap`）。表の `--ll-cell-padx` と `data-overflow` に当てる。自動の幅（`estimate`）もいまの余白で決める。

## カード（行をダブルクリック。機能: 使う／使わない）

- `lotlist-card.js`（`window.LotListCard`）。一覧は `mount` で「いまの一覧」（行・表・列・ロット番号の列・ロットの見分け方・計算画面で開く・カードの行の印・知らせ）を渡す。
- 窓は浮き窓（`TPA.floatPanel`、位置と大きさ `tpa.lotlist.cardRect.v1`、覚えが無いときは右寄せ）。大きさは4辺と4隅の取っ手（窓は `overflow:clip` なので CSS の `resize` は効かない）。
  動かす・大きさを変えるあいだは画面の端とほかの浮き窓（`[data-float]`）の辺へ 8px で吸い付き（Alt で吸い付かない）、位置と大きさを数で出す。Alt+矢印・Alt+Shift+矢印で 10px（Ctrl で 1px）。
- いくつも開く（最大8枚）: ダブルクリックは「残す」にしていないいちばん新しいカードの中身を替える。無ければ新しいカード（前のカードから少しずらす）。Ctrl＋ダブルクリックはいつも新しいカード。
  「並べる ▾」で並べ方を絵で選ぶ（`LAYOUTS`: 横に並べる・縦に積む・格子・右半分に・重ねる。小さくなりすぎる並べ方は格子に替える）。
  開いているカードは一覧の件数の横の棚（`#llCardShelf`）に札で並ぶ（前のカードは藍の枠・📌・×・並べる・違いを強調・全部閉じる）。「違いを強調」（`tpa.lotlist.cardDiff.v1`。既定は使わない）でカードどうし値が違う項目に印。
  一覧では、カードで見ている行すべてを藍の枠で示す。Esc は触っているカード（一覧に居るときは前のカード）を閉じる。
- 配置は表ごと（`tpa.lotlist.card.v1`。どのカードも同じ）: 並び（ドラッグ、`TPA.dragSort`）・幅（1〜4枠・1行。自動の列数を超える幅はその列数に収める）・高さ（標準・2倍・3倍）・隠す・列数（自動／1〜4）・文字（小中大）・空欄を隠す。
  まだ隠す・戻すをしていない表は、一覧の表示列で隠した列を隠す（並びも表示列と同じ）。値の見え方は一覧のセルと同じ `LotListColumns.cell`。
- ◀ ▶・←→ で一覧の前後の行（まとめているときはまとめた順）。同じロットの行が一覧のそのページにあれば札で切り替える。
  一覧が読み直されたら同じ行（値がすべて同じ行）を探し直し、無ければ開いたときの値のまま「いまの一覧にありません」と言う。計算画面へ移る・表を替えると閉じる。

## 表示列（WaveLog の列の設定と同じ）

実装: `app/static/js/lotlist-columns.js`（列の設定・窓・見出しの操作）、`lotlist-rules.js`（読み替えルールの判定と編集の窓）、`list-formula.js`（WaveLog の式の計算器をそのまま）。

- 1つの表ごとに `{order, hidden, widths, locks, names, formats, aligns, formulas, rules, builds}`（対象 `lotlist:<表>`・localStorage `tpa.lotlist.layout.v1`）。saved／draft（窓で触っている途中）／live（見出しをドラッグ中）の3層。
- 値の段取り: 作り方の式 → 読み替え（当たればその言葉と色で確定）→ 当たらなければ値の整え方 → 整えられなければ元の値。
- 計算列は表示だけ（並べ替え・絞り込みの対象にしない。見出しに「式」）。式は `eval` を使わない自前の計算器。
- 読み替えルール: localStorage `tpa.lotlist.rules.v1`。行＝上から順（最初に当たった行）・条件の無い行＝既定。
  行の中の条件は `join`（"and"／"or"。無ければ "and"＝以前のルールと同じ）でつなぎ、and が or より先に結ぶ（`orGroups`: or で区切ったまとまりのどれかが、中の条件すべてに当たれば、その行）。「式にする」は `(… and …) or (…)` を作る。
  かっこ＝まとまり `{ join, items: [...] }`（items は条件かまた別のかっこ。画面では3段まで）。判定 `holds` と式 `logic` は同じ再帰で、かっこの中を先に決める。
  画面ではかっこを枠で描き（開き・閉じが必ず対になる）、場所は `data-path`（"行.位置.位置…"）で指す。中が空になったかっこは消す（`prune`）。各行に「読み方」（かっこは（ ）、同じ段で かつ が先に結ぶ所は［ ］）。比べる値は「元のデータ」か「表示の値」（式→値の整え方の後）。
- この列の作り方（版 3.22.0〜）: 読み替えルールと同じ組み立ての別窓（`lotlist-rules.js` の `makeEditor({kind: "formula"})`・`openFormula`）。
  「組み立てる」は読み替えルールと同じ行（上から順・かつ／または／かっこ・左辺 この列／他の列／式・右辺 固定値／他の列／式・出す値）で、
  `toFormula` で同じ意味の式にして当てる（色は無い。計算列は「この列」が無く、出す値の空欄は空欄）。組み立てた行は `builds[列]` に覚え、
  式がその組み立てから作った物のときだけ「組み立てる」で開き直す。「式を書く」は広い欄＋部品から作る（`formula-builder.js`。条件で分けるは出さない）。
  「当てる」で表示列の設定の下書きに入る（表示列の設定の「保存」で確定）。窓の中で打っている間は一覧も表示列の窓も描き直さず、
  打つ手が止まってから試した結果だけを描く（`ui-eval-formula.mjs` が入力の遅れを、同じ画面の素の欄と交互に 3 回ずつ打って、平均と 95 パーセンタイルで比べる）。
  固定配置の窓・候補の台は組み直しの区切りにならない（Chromium）ので、式の欄は包み（グリッドの子）の中で大きさを数で決めて `contain:strict`、候補は台の中の普通の箱（`.fx-suggest-layer`）に置く。こうしないと 1 字ごとに後ろの一覧（固定列のセルで約 4 万個）から配置を計算し直す。
  元の列を作り替える式の［その列］・［この列］は作り替える前の値（`baseRow(t, row, self)`）。
- WaveLog との違い: 置き場はこの PC（WaveLog はマスタ DB で PC 間・利用者ごとに共有）。列ごとの並べ替えの決まり（読み替え後の字で並べる等）と列の仮想描画は持ち込んでいない。

### 作業でまとめる（版 3.20.0〜。`services/work_summary.py`・`services/shifts.py`・画面は `lotlist-work.js`）

## 色付け（条件付き書式。版 3.21.0〜。絞り込みの派生。`lotlist-marks.js`）

利用者の指示「フィルタの派生機能で、条件付き書式のような、作った条件に該当した部分だけ、フィルタをかけるのではなく、書式を反映するもの」。

- 1 組 ＝ 条件の並び（かつ。絞り込みと同じ列・比べ方・値）＋色（赤・黄・緑・青・紫・灰。意味で固定）＋当てる所（条件の列のセル／行全体）＋使う／使わない。
  同じ所に何組も当たったら、上の組が勝つ。1 つの表で 8 組まで。表ごとにこの PC に覚え、表示の設定・共有の書式にも入る。
- **判定はサーバー**（`lot_list.mark_rows`・`mark_counts`。デスクトップ版は `lotlist.rs` の同じ名前の関数）。問い合わせの `marks`（組の並び）を受け、
  引いたページの行だけを `VALUES` の一時の表にして、絞り込みと同じ式（`build_filter_where`）を当てる。行を引く SQL（ふつう・ロットでまとめる・
  作業でまとめる）は変えないので、どのまとめ方でも同じに効き、「絞ると出る行」と「色が付く行」は食い違わない。答えは組ごとの
  「そのページで当たった行の位置」（`marks`）と「絞り込んだ全件で当たった数」（`markCounts`。凡例に出す）。
  組の中に無い列・使えない比べ方の条件が 1 つでもあれば、その組は当てない（外して当てると広く当たってしまう）。
- 画面は、当たった印を受け取った直後に行そのもの（WeakMap）へ結ぶ（段のために画面が行を並べ替えても外れない）。
- 画面（7 案＋2 回目で選んだ: `program/tools/ui-proposals/2026-10-marks*.mjs` の M2）: 道具の行の入口「●● 色付け n ▾」（閉じても効いている色と数が見える）
  → 面: 組の一覧（使う／使わない・色・当てる所・↑・×）と「色付けを作る」／件数の行の凡例の札（押すと消す／付ける。版 3.25.0 から、効いている物の色付けのタブで開く面の中）／「列で絞り込む」の行の「色を付ける」
  （打っている条件を、絞り込む代わりに色に）。Excel に出力も同じ色で塗る（`xlsx-writer.js` の `paint`）。
- 試験・評価関数: `tests/test_lot_list.py` の MarkTests（同じ条件で絞った行とちょうど同じか・全件の数・分けて渡しても同じ）・`test_work_summary.py`
  （作業でまとめた並び）・Python と Rust の突き合わせ（`lotlist_fixture.CASES` の marks）・`program/tools/ui-eval-marks.mjs`（本物の画面 10 項目）・
  `xlsx-check.mjs`（塗り）。
